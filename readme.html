MVP Goals & Intentions

Bell is a Progressive Web App (PWA) designed to provide instant, high-priority home communication between partners in separate rooms. It solves the issue of missing standard messages (like SMS or WhatsApp) when one partner needs urgent physical help or quick attention.

Core MVP Features

  • Role Isolation: Devices configured as Partner 1 (Ringer) see the primary bell interface to call for help. Devices set as Partner 2 (Receiver) see incoming alerts and response controls.
  • Urgent Push Alerts: Integrated with ntfy.sh (Priority 5, urgent tags) to trigger loud notification alarms on Android, even if the screen is locked.
  • Interactive Responses: Receiver can respond with quick choices ("On My Way!", "Give Me 5 Min", or custom text) that instantly update the Ringer's screen.
  • Serverless Database (Optional): A Google Apps Script backend bound to a Google Sheet automatically logs all events, durations, and replies, providing shared history.
  • Offline-First / PWA: Fully installable standalone app, utilizing a service worker to cache assets and load immediately in offline conditions.

User Guide

Follow these steps to set up and use Bell with your partner:

Step 1: Open and Install the App

Open the live PWA link: https://good-enough-productions.github.io/bell/ on both devices. In Chrome, click the Install icon in the address bar to run it as a standalone app on your home screen or desktop.

Step 2: Assign Roles

Go to the Settings tab:

  • Device A (e.g. Desktop): Select Partner 1 (Ringer) and click Save Settings.
  • Device B (e.g. Phone): Select Partner 2 (Receiver) and click Save Settings.

Step 3: Setup Phone Alerts (ntfy)

  1. On your phone, install the free ntfy app from the Google Play Store.
  2. Open the ntfy app, tap + (Subscribe), and enter a shared secret topic name (e.g. bell-home-alert-13579).
  3. In the Bell PWA Settings tab, type this exact same topic name under ntfy Topic Name.
  4. Click Send Test Notification to verify your phone rings!
Note for Android: Ensure the ntfy app has battery optimizations disabled and permission to send notifications to ensure alerts arrive instantly.

Developer Guide

Instructions for developing, updating, and deploying the Bell codebase.

Repository Structure

  • index.html: Responsive UI layout styled with Vanilla CSS.
  • app.js: Main application logic, handling PWA tabs, state syncing, ntfy calls, and local storage fallback.
  • sw.js: Service worker code that handles asset caching and push notifications.
  • gas_sheet_project/: Google Apps Script folder managed by clasp. Contains:
    • Code.js: Backend API code handling spreadsheets logging and feedback.
    • appsscript.json: Apps script manifest config.

Architectural Notes

  • MVC-Lite Separation: app.js is structured to cleanly separate remote data fetching (fetchRemoteState), local state mutation (updateStateFromRemote, syncLocalStatus), and DOM rendering (updateUI).
  • Centralized Store: All localStorage interactions run through a centralized Store object to prevent key typos and unify JSON serialization.

Local Development & Clasp Setup

The Apps Script is linked directly to your Google Sheet using Google clasp:

# Install dependencies
npm install -g @google/clasp

# Login to Google clasp
clasp login

# Push modifications to sheet Apps Script
npx clasp push -f

# Redeploy Web App (keeps the same URL)
npx clasp deploy -i <DEPLOYMENT_ID> -d "Update description"
Crucial Deployment Scope: Keep the Apps Script scopes limited. Do not introduce UrlFetchApp calls to prevent triggering Google's security blocks, which require manual re-authorization from the user.

Technical Roadmap

Phase 1: Stabilization (Completed)

Role-based screens, direct JSON client-side ntfy triggers, and database-less localStorage fallback features are completely stable.

Phase 2: Feedback & Help (Completed)

Expose a built-in user guide and feedback submission form in Settings, automatically logged to the spreadsheet database.

Phase 3: iOS Web Push Support

Add standards-based Web Push protocol features using VAPID keys to support native lock-screen alerts on iOS 16.4+ without relying on the ntfy app.

Phase 4: Custom Audio Upload

Allow users to upload or choose custom MP3 chime sounds to play on their device when a bell is rung.

Lessons Learned

1. Progressive Web App Caching Lifecycles

PWAs cache files very aggressively. A normal page refresh (F5) will still serve the older JS file from the service worker cache. To bypass this, we implemented an aggressive auto-updater inside index.html that listens for new service worker installations and immediately reloads the page to activate the update.

2. Web App CORS Limitations

Google Apps Script Web Apps do not support CORS headers for POST requests from external domains. We utilize mode: 'no-cors' for database updates, which returns an opaque response, and synchronize the client-side state using an asynchronous GET poll (which supports redirects).

3. Stale State Race Conditions

Because writing rows to Google Sheets takes a few seconds, a status poll fired right after a cancellation or response could fetch the old PENDING state and revert the UI. We resolved this by implementing an optimistic UI lock (dismissed ring ID tracker) to block old statuses from rendering.

Backlog & Bugs

No Active Bugs: All critical loops, role identity mismatches, and local storage queue bugs have been fully resolved.

Backlog / Planned Tasks

  • Offline Action Queue: Store pending gasPost requests when offline and re-attempt them upon network restoration.
  • Multicast Rooms: Expand database columns and topics to allow group/family alert channels (more than 2 partners).
  • Chime Sound Settings: Let users adjust notification volume or select from pre-recorded bell ring types directly in Settings.
  • Status Polling Inactivity Sleep: Pause status polling loop after 1 hour of browser inactivity to conserve device battery and avoid hitting Google API limits.
